The Audio Video API is an asynchronous media processing platform for ultra-high-definition (UHD) video and audio enhancement. You submit a source video by URL, the platform downloads it, applies the enhancement you requested, and uploads the result to cloud object storage — all without you managing any transcoding infrastructure.

Every operation follows the same simple pattern: **create a task, track its progress, download the result**.

## Capabilities

The platform exposes four AI-powered enhancement capabilities, each with a dedicated task creation endpoint:

| Capability | Endpoint | What it does |
| ---------- | -------- | ------------ |
| [SDR to HDR](./sdr-to-hdr) | `POST /api/v1/task/sdrToHdr` | Converts standard dynamic range video to HDR (PQ/HLG), or HDR to HDR Vivid. |
| [Super Resolution](./super-resolution) | `POST /api/v1/task/superResolution` | Upscales video with an AI model, up to 4K or a custom resolution. |
| [Frame Interpolation](./frame-interpolation) | `POST /api/v1/task/intelliFrame` | Intelligently interpolates frames to raise the frame rate, up to 60 fps. |
| [Audio Enhancement](./audio-enhancement) | `POST /api/v1/task/audio` | Converts 2D stereo audio into immersive 3D multi-channel audio (up to 7.1.4). |

Once a task is created, the same task management endpoints work for all capabilities:

| Operation | Endpoint | Method |
| --------- | -------- | ------ |
| Get task detail | `/api/v1/task/detail` | `GET` |
| Get task progress | `/api/v1/task/progress` | `POST` |
| Cancel task | `/api/v1/task/cancel` | `POST` |

The complete, interactive API reference is available in the [API Reference](/api) section.

## How it works

Tasks are processed asynchronously by a pool of GPU workers. Internally, each task runs through a highly parallel pipeline — the video is sliced into segments, transcoded in parallel, merged back together, and then merged with the enhanced audio track if audio processing was requested.

```ansi title="Task pipeline"
[1;36m  create task          download            analyze           process (parallel)          upload[0m
[36m┌────────────┐   ┌──────────────┐   ┌────────────────┐   ┌─────────────────────┐   ┌──────────────┐[0m
[36m│ POST task  │[0m [32m→[0m [36m│ fetch source │[0m [32m→[0m [36m│ probe metadata │[0m [32m→[0m [36m│ video path (slices) │[0m [32m→[0m [36m│ cloud object │[0m
[36m│  (queued)  │   │ from inputUrl│   │ with mediainfo │   │ audio path (2D→3D)  │   │   storage    │[0m
[36m└────────────┘   └──────────────┘   └────────────────┘   └─────────────────────┘   └──────────────┘[0m
```

Key characteristics:

- **Asynchronous by design** — Task creation returns immediately with a `taskId`. Processing may take from minutes to hours depending on file size and requested enhancement.
- **Real-time progress** — Every task reports download, video, audio, and upload progress as values between `0` and `1`. See [Task Lifecycle](./task-lifecycle).
- **Cloud storage delivery** — Output files are uploaded to cloud object storage (Alibaba Cloud OSS or Azure Blob, depending on deployment). The `outUrl` field in the task detail is a directly downloadable URL. See [Output Files & Storage](./output-files).
- **Automatic cleanup** — All intermediate files (source copy, slices, intermediate renders) are deleted from the workers as soon as the task finishes.
- **Cancellation** — Waiting or running tasks can be cancelled at any time.

## Base URL

All requests are sent to the platform's base URL with the `/api/v1` prefix:

```ansi title="Base URL"
[36mhttp://apis.mls-tech.cn[0m/api/v1/task/[33m{operation}[0m
```

:::note

The examples in this documentation use the production base URL `http://apis.mls-tech.cn`. If your environment uses a different endpoint, replace the host in the examples accordingly.

:::

## Authentication

Every request must include your `callerId` and `apiKey` credentials. The API uses simple key comparison authentication, and each caller can only see and operate on their own tasks.

See [Authentication](./authentication) for details.
